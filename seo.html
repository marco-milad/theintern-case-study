Getting a React app onto Google's first page

From barely indexed to page one for “internships in Cairo”, without ads.

TheIntern.app is a single-page React app. Students loved it; Google couldn't see it. This is how I found out why, what I changed in the product and the backend, and what the first week of real Search Console data showed.

Problem

The starting point

The site was barely indexed. Search Console showed internship pages flagged as soft 404s, and searches students actually make (“internships in Cairo”, “remote internships”) never showed us at all.

The product itself worked. The problem was what Google received: a React shell that only fills in after the browser loads data from the API. And robots.txt blocked that API path, so Google's renderer got empty pages and treated real job postings as missing.

Diagnosis

How I found it

  • URL Inspection in Search Console: I compared the rendered HTML Google saw with what a student sees. The job details simply weren't there.
  • Rich Results Test: no JobPosting data, so the internships could never appear in Google Jobs.
  • Page indexing report: the soft 404s pointed at exactly the pages that load their content from the API.

That turned a vague “SEO is bad” into a concrete engineering problem: render what needs to rank on the server, and describe it in a way Google understands.

Problem → work → result

What I built

Rendering

Server-render what has to rank

Before
Every page was an empty shell until JavaScript ran and the API answered.
Work
FastAPI now serves internship, city and remote pages as real HTML: title, description, canonical URL, links and the listing itself. The React app takes over for students once it loads. Crawlers that send HEAD requests get proper answers too.
Result
Google reads the same content a student sees, with no dependency on a blocked API.
Structured data

Eligible for Google Jobs

Before
No machine-readable job data.
Work
Every internship carries JobPosting data, including remote work and the real application deadline, so a posting drops out of Google Jobs when it closes instead of going stale.
Result
Postings pass the Rich Results Test and are eligible for the Google Jobs box above the regular results.
Content

Pages for real searches

Before
One homepage trying to rank for everything.
Work
A page for each search students actually make: Cairo, Dubai and remote internships, each listing real openings. Plus guides in Arabic and English answering questions students ask, like which companies offer internships in Cairo.
Result
The Arabic guide became the single biggest source of clicks, ahead of the homepage.
Hygiene

Remove what Google trips on

Before
Old URLs returned empty pages with a 200 status, and the same internship was reachable under different URLs.
Work
A sitemap of live postings, one canonical URL per internship shared by the app and the crawler pages, real 404s for missing pages, and 301 redirects for legacy URLs Google had flagged.
Result
Google's crawl budget goes to pages that matter, and every link points at one version of each page.

Takeaways

What I learned

  • SEO for a single-page app is a rendering problem first. Keywords don't matter if Google receives an empty page.
  • Arabic content is an open lane. Fewer sites answer students' questions well in Arabic, and our Arabic guide outperformed every English page.
  • Measure, then build the next page. Search Console shows which searches we almost win; those decide what gets written next.
In progress

What's next

  • Track how often postings appear in the Google Jobs box.
  • More guides for the searches we already appear in but rank lower for, such as “internship apps” and “online internships”.
  • Split the JavaScript bundle so pages load faster on phones, which is where most clicks come from.
