TheIntern.app

Students keep hearing “you need experience” for internships that are supposed to give them experience.

TheIntern.app is an AI job-simulation platform. Students complete real tasks designed with companies, get AI feedback and a verified certificate, and are matched to internships based on what they actually did. It runs on the web, Android and iOS, in Arabic and English, with Egypt as its main market.

Architecture

Every client talks to one FastAPI backend behind nginx. Pages that need to rank on Google are rendered on the server, so crawlers see real content instead of an empty app shell. Personal files never sit in a public folder; they are served through short-lived signed links.

Purple marks the backend I own; amber marks outside services.

Key work

Growth

Getting found on Google

Problem
The site was barely indexed. Google marked job postings as soft 404s because robots.txt blocked the API the pages loaded their data from.
Work
Server-rendered landing pages per city, JobPosting structured data with real deadlines, a clean sitemap, real 404s, and two bilingual career guides answering what students search for.
Result
First page of Google for “internships in Cairo”, #1 for the brand on Google, Bing and DuckDuckGo, and postings eligible for Google Jobs. Read the SEO deep dive →
Security

Protecting students’ CVs

Problem
Uploaded CVs and documents lived in folders that could be reached by URL.
Work
Every personal file is now served through a signed link tied to the viewer, with short expiry for documents. nginx denies the old folders outright, and internal services were locked to the server itself.
Result
No personal file is reachable without a valid, time-limited link, and none can appear in search results.
Reliability

AI that keeps working

Problem
A provider outage took simulation feedback down with it.
Work
A self-healing fallback chain across models, so a failing provider is skipped automatically.
Result
Students keep getting feedback when one model is unavailable.
Reliability

Sign-in under real load

Problem
OAuth sign-in failed for about three in four attempts once production ran four workers.
Work
Traced the failure to state that did not survive across workers and made the flow work regardless of which worker handles each step.
Result
Google and LinkedIn sign-in work reliably in production.
Shipping now

A sign-up students finish

Problem
Testing on a real phone exposed two silent blockers in the mobile sign-up: a trailing space from keyboard suggestions and Google/LinkedIn prefill both left “Next” disabled with no message. On the web, most students who verified their email stopped at a long education form.
Work
Fixed both blockers, then redesigned the flow: account first with name, email, password and a code, then one required “Help us match you” step. Majors can be picked in Arabic, including Egyptian faculty names like حاسبات and تجارة, and every step is now tracked.
Result
Matching keeps the data it needs, and we can see exactly where students stop.
Product

Changing the business without a release

Problem
The team wanted to hide payments to grow sign-ups, and to be able to bring them back later.
Work
A server-side flag that web and mobile read at startup. It fails closed, keeps existing billing and renewals live, and toggles from the admin console.
Result
Pricing turns off or on in seconds, with no app-store review.

How releases ship

  • Every change runs the full test suite before it is committed.
  • Each production deploy takes backups first and is verified with live checks afterwards.
  • Guards in the build stop work landing in the wrong place.

Built for this market

  • Arabic and English, with real right-to-left layouts.
  • The locale layer is in place across web and both apps, so adding a language is translation work rather than a rebuild.
  • Phone formats and universities for Egypt and the Gulf.
  • Application deadlines that close postings and remove them from search on time.
